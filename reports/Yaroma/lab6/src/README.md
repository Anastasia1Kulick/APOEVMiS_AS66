# Лабораторная работа №6. Cisco Packet Tracer. Вариант 12

Ярома А. И., АС-66. По методичке это лабораторная №1 части 4 (с. 369–371). Схема с маршрутизаторами и исходные адреса приведены на с. 362–363. Здесь приведены настройки и результаты проверок в Packet Tracer 9.0.1.

В этой папке находятся три проекта. `lab6_practice.pkt` — тренировочный пример из §2.2. `lab6_part1_variant12.pkt` — сеть с семью ПК. `lab6_part2_variant12.pkt` — начальная настройка двух маршрутизаторов. Файлы сформированы локально средствами PKT-CORE для формата Packet Tracer 9.0.1. Все три проекта открыты и проверены в симуляторе. Скриншоты включены в [отчёт](../rep/report.pdf).

## Часть 1. Локальная сеть

Сначала выполнить пример из §2.2 (с. 358–360). Соединить Switch0 и Switch1 перекрёстным кабелем. PC0 и PC1 подключить к Switch0, PC2 и PC3 — к Switch1 прямыми кабелями. Адреса PC0–PC3 по таблице 3: `192.168.1.2`, `192.168.1.3`, `192.168.1.4`, `192.168.1.5`, маска `255.255.255.0`, поле шлюза пустое. Проверка из примера — `ping 192.168.1.2` с PC3.

В тренировочной и самостоятельной сетях использованы коммутаторы Switch-PT. В самостоятельной топологии четыре коммутатора соединены цепочкой `SW2 — SW4 — SW5 — SW3`. ПК на рисунке подписаны PC0–PC6. Ниже те же позиции пронумерованы PC1–PC7 по таблице задания. Имена PC1–PC7 заданы в свойствах устройств. Команда `hostname` в командной строке PC-PT возвращает `Invalid Command`. Порты выбраны для проекта.

| ПК | Позиция на рисунке | Порт коммутатора | Последний октет | IP |
|---|---|---|---:|---|
| PC1 | PC0, сверху слева | SW2 Fa0/1 | 1 + 5×12 = 61 | 12.25.37.61 |
| PC2 | PC1, слева | SW2 Fa1/1 | 2 + 3×12 = 38 | 12.25.37.38 |
| PC3 | PC2, снизу слева | SW4 Fa0/1 | 3 + 4×12 = 51 | 12.25.37.51 |
| PC4 | PC3, снизу по центру | SW4 Fa1/1 | 4 + 2×12 = 28 | 12.25.37.28 |
| PC5 | PC4, снизу справа | SW5 Fa0/1 | 5 + 3×12 = 41 | 12.25.37.41 |
| PC6 | PC5, справа | SW3 Fa0/1 | 6 + 2×12 = 30 | 12.25.37.30 |
| PC7 | PC6, сверху справа | SW3 Fa1/1 | 7 + 4×12 = 55 | 12.25.37.55 |

Сеть `12.25.37.0/24`. Маска всех ПК `255.255.255.0`. Шлюз оставить пустым. Во всех адресах первые три октета по таблице 4 равны `v`, `1+2v`, `1+3v`. Пример на с. 371 даёт для PC1 при v=7 последний октет 35, хотя формула `1+5v` даёт 36. Здесь использована формула таблицы 4.

ПК соединять с коммутаторами прямым медным кабелем через FastEthernet0. Связи между коммутаторами выполнить перекрёстными кабелями.

| Соединение | Порты |
|---|---|
| SW2 — SW4 | Fa2/1 — Fa2/1 |
| SW4 — SW5 | Fa3/1 — Fa2/1 |
| SW5 — SW3 | Fa3/1 — Fa2/1 |

Проверена конфигурация PC1, PC3, PC5 и PC7 командой `ipconfig`. Получено четыре ответа из четырёх в каждой проверке: PC1 → PC7 (`ping 12.25.37.55`), PC3 → PC6 (`ping 12.25.37.30`), PC5 → PC2 (`ping 12.25.37.38`), PC7 → PC4 (`ping 12.25.37.28`). В тренировочном проекте PC3 получил четыре ответа из четырёх от PC0.

## Часть 2. Начальная настройка маршрутизаторов Cisco

Схема: `PC1 — SW1 (2950-24) — R1 (1841) — R2 (1841) — PC2`. Для последовательного соединения нужны модули с интерфейсом Serial0/1/0 на обоих 1841. Вставить модули в выключенные маршрутизаторы. Кабелем Serial DCE сначала выбрать порт R1, затем R2. На R1 задать `clock rate 64000`.

| Узел | Интерфейс | IP | Маска | Шлюз |
|---|---|---|---|---|
| PC1 | FastEthernet0 | 192.168.1.22 | 255.255.255.0 | 192.168.1.13 |
| R1 | FastEthernet0/0 | 192.168.1.13 | 255.255.255.0 | — |
| R1 | Serial0/1/0 (DCE) | 192.168.2.13 | 255.255.255.0 | — |
| R2 | Serial0/1/0 (DTE) | 192.168.2.14 | 255.255.255.0 | — |
| R2 | FastEthernet0/0 | 192.168.3.13 | 255.255.255.0 | — |
| PC2 | FastEthernet0 | 192.168.3.22 | 255.255.255.0 | 192.168.3.13 |

По правилу `192.168.x.(y+v)` в исходной адресации меняется четвёртый октет адресов и шлюзов. Сети остаются `192.168.1.0/24`, `192.168.2.0/24`, `192.168.3.0/24`. PC1–SW1 и SW1–R1 подключить прямым медным кабелем, R2–PC2 — перекрёстным кабелем. У R1 и R2 использовать FastEthernet0/0 для LAN.

При восстановлении конфигурации на CLI ответить `no`, затем провести конфигурацию командами из `R1.cfg` и `R2.cfg`. Нажать Enter на запрос имени файла при сохранении `copy running-config startup-config`. Пароли в файлах предназначены только для проекта в симуляторе.

Результаты проверки по §3.2:

| Проверка | Результат |
|---|---|
| `show ip interface brief` на обоих маршрутизаторах | Fa0/0 и S0/1/0 имеют свои адреса и состояние `up/up` |
| `show ip route` на R1 | Прямые сети 192.168.1.0/24 и 192.168.2.0/24 |
| `show ip route` на R2 | Прямые сети 192.168.2.0/24 и 192.168.3.0/24 |
| PC1 → 192.168.1.13, PC2 → 192.168.3.13 | Ответы локальных шлюзов |
| R1 → 192.168.2.14, R2 → 192.168.2.13 | Ответы через Serial |
| PC1 → 192.168.2.13, PC2 → 192.168.2.14 | Ответы своих маршрутизаторов по собственным адресам Serial при верном шлюзе на ПК |
| PC2 → 192.168.1.22 | 0 ответов из 4. R2 вернул `Destination host unreachable`, поскольку у него нет маршрута к LAN R1 |

Статические маршруты относятся к следующей лабораторной работе. Скриншоты таблиц маршрутизации и проверок связи есть в отчёте.
