# Дополнение к лабораторной №5. Название книги в Wireshark

Для опыта загружена [публичная страница «Матабар» Кирилла Клеванского](https://author.today/work/337592). На отдельном TCP-соединении выполнен один запрос HTTPS без входа в аккаунт. Клиент запросил HTTP/1.1 с заголовком `Connection: close`. Запись остановлена после завершения соединения.

Откройте `matabar.pcapng` в Wireshark. В файле 117 пакетов и ключи TLS только для этого демонстрационного сеанса. Wireshark читает их из файла захвата. Отдельно выбирать файл ключей в настройках не требуется.

## Найти название и автора

Вставьте в строку фильтра отображения и нажмите Enter.

```wireshark
http.response.code == 200 && http.request.uri == "/work/337592" && http.file_data contains "Матабар - Кирилл Клеванский"
```

Отобразится пакет №112 с ответом `200 OK`. Поле `http.file_data` содержит тело HTTP-ответа, собранное из сегментов. В HTML видно поле `<meta property="og:title" content="Матабар - Кирилл Клеванский" />`.

Чтобы показать это поле на защите, щёлкните по пакету №112 правой кнопкой, выберите **Follow → TLS Stream**, установите отображение **UTF-8** и найдите `og:title`. В ответе видны название и имя автора. Пакет №16 содержит исходный `GET /work/337592`.

## Показать закрытие соединения

```wireshark
tcp.stream == 0 && frame.number >= 114
```

Пакеты №114 и №115 содержат `FIN, ACK` с двух сторон. В №116 и №117 обе стороны подтверждают закрытие. Полный файл включает начало соединения, обмен данными и завершение. Фильтры изменяют только список пакетов на экране.

HTTPS шифрует HTTP-запрос и ответ. При проверке копии файла без ключей Wireshark видел TCP и TLS, а фильтр по названию не находил совпадений. Анализ выполнен в Wireshark. Захват сделан PktMon в точке Raw IPv4 внутри VPN.
