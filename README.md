## Порядок работы

1. Делаем **форк** этого репозитория к себе в аккаунт.
2. Выполняем лабораторную работу.
3. Коммитим отчёт и файлы проекта в свою ветку форка.
4. Делаем **Pull Request** в `main` этого репозитория.
5. Дожидаемся автоматической проверки (см. ниже) и результатов проверки преподавателем.

### Команды git

1. `git clone <url-адрес вашего форка>` — клонирование в локальную папку
2. `git add *` — добавление всех файлов в список отслеживаемых
3. `git commit -m "message"` — формирование коммита
4. `git push` — отправка изменений в свой форк

После этого на странице своего форка на GitHub нажимаем **Contribute → Open pull request**, проверяем diff и жмём зелёную кнопку **Create pull request**.

## Куда класть файлы

```
reports/<Фамилия>/<Номер_лабораторной>/rep/   — отчёт (pdf/docx)
reports/<Фамилия>/<Номер_лабораторной>/src/   — файлы проекта:
    - .asm файлы (лабы по ассемблеру)
    - .pkt / .pkа файлы Cisco Packet Tracer (топологии сетей)
    - .pcapng файлы Wireshark (перехваченный трафик) + .txt/.cfg с конфигурацией устройств, если применимо
```

Пример:
```
reports/ivanov/lab1/rep/report.pdf
reports/ivanov/lab1/src/topology.pkt
```

## Проверка при Pull Request

Курс не предполагает автоматических функциональных тестов (ассемблер, топологии в Packet Tracer, настройка протоколов в Wireshark не проверяются программно). Вместо этого при каждом PR, затрагивающем `reports/**`, автоматически запускается **проверка на уникальность**:

- Текст отчёта (`rep/*.pdf`, `*.docx`, `*.txt`, `*.md`) сравнивается со всеми ранее загруженными отчётами по **той же лабораторной работе** (текстовое сходство, TF‑IDF + косинусная близость).
- Файлы проекта (`src/*`) дополнительно сравниваются **побайтово (по хэшу)** — это ловит случаи, когда студент просто скопировал чужой `.pkt`/`.pcapng`/`.asm` файл целиком.
- Результат публикуется в Job Summary Pull Request'а:
  - **дубликат** (совпадение хэша или похожесть текста ≥ 90%) → проверка падает (красный крестик), PR нельзя мержить без ручного разбора;
  - **подозрительное сходство** (60–90%) → проверка проходит, но в Summary выводится предупреждение для проверяющего;
  - иначе — проверка зелёная.
